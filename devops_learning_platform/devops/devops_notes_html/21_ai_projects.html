AI and MLOps project lab

Progressive projects for building, securing, deploying, and operating AI systems.

Project 1: AI quality gate

Build a CI job that validates prompt templates, checks structured-output schemas, runs a fixed evaluation set, and fails when quality or safety scores fall below thresholds.

Checkout -> install dependencies -> lint -> unit tests -> evaluation set -> security checks -> publish report -> approval

Skills: Jenkins, Python, JSON Schema, pytest, report publishing, thresholds, and artifact retention.

Project 2: Secure RAG assistant

Build a document question-answering service with ingestion, chunking, embeddings, vector retrieval, tenant filters, citations, refusal behavior, and an evaluation dataset.

Required controls: document access rules, prompt-injection tests, PII redaction, source citations, output validation, request limits, and audit events.

[SECURITY] Never allow the model to bypass application authorization. A retrieved document must be filtered for the requesting user's access before it enters the prompt.

Project 3: AI service on Kubernetes

Containerize an inference API, deploy it with Kubernetes, expose health endpoints, configure resource requests and limits, and monitor latency, errors, queue depth, and token usage.

Operations: readiness and liveness probes, horizontal scaling, secret references, rolling deployment, canary release, logs, traces, and rollback.

Project 4: Model promotion pipeline

Train or package a model, store its metadata in a registry, compare it with the current production version, require approval, deploy a canary, and promote only when service and quality signals remain healthy.

Evidence: commit ID, data version, model digest, evaluation report, approval identity, deployment ID, and rollback artifact.

Project 5: AI observability dashboard

Create dashboards and alerts for request rate, time to first token, total latency, errors, provider quota, input/output tokens, retrieval hit rate, groundedness, refusal rate, and tool failures.

Alert examples: provider outage, rising latency, retrieval failure, unexpected cost increase, sensitive-output detection, and expired model credentials.

Project completion checklist

Each project should include a README, architecture diagram, local run instructions, tests, security assumptions, cost notes, dashboards, failure scenarios, and a rollback or shutdown procedure.

Start locally with mock model responses and small datasets. Add a real provider only after validation, secret handling, cost limits, and data-retention decisions are documented.
