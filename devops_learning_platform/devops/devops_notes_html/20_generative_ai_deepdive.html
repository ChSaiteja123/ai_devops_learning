Generative AI engineering deep dive

Designing reliable, secure, observable, and cost-aware AI applications.

Production architecture

Client -> API gateway -> validation -> model router -> retrieval/tools -> output checks -> response | metrics, traces, audit, cost

Keep provider-specific code behind an adapter. Separate request validation, authorization, retrieval, tool execution, output validation, and observability so each control can be tested independently.

Prompt and context engineering

Define role, task, trusted instructions, untrusted content, constraints, output schema, and refusal behavior. Retrieve only relevant context and preserve source identifiers for citations.

Use low variation for extraction and tool arguments. Use evaluation data to choose model and decoding settings rather than relying on intuition.

[SECURITY] Prompt instructions are not authorization. Validate permissions in application code before retrieval or tool execution.
[WARNING] Retrieved documents and web pages can contain prompt injection. Treat them as data, not as system instructions.

RAG quality

A robust RAG pipeline cleans documents, preserves headings, chunks complete ideas, stores metadata, filters by tenant and permissions, retrieves candidates, optionally reranks them, and evaluates grounded answers.

Measure retrieval recall and precision independently from response quality. Re-index when source documents, permissions, or embedding models change.

Tools and agents

Receive request -> classify risk -> retrieve -> plan allowed action -> approval if needed -> validate tool arguments -> execute one tool -> validate result -> respond -> audit

Bound the number of steps, time, tokens, retries, and tool permissions. Prefer deterministic workflows for known business processes.

Evaluation and observability

Track correctness, groundedness, refusal behavior, tool-call accuracy, latency, token cost, provider failures, and sensitive-data incidents. Store prompt version, model version, source versions, and safe trace identifiers.

Test normal, ambiguous, adversarial, oversized, and unauthorized requests. Include direct and indirect prompt injection in red-team testing.

Deployment checklist

Use timeouts, bounded retries, rate limits, redaction, schema validation, secret management, human approval for high-impact actions, cost budgets, provider failover policy, and a rollback path for prompt, model, index, and policy changes.
