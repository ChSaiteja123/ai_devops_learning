Docker
========================

PURPOSE / OVERVIEW
--------------------------------------------------------------------------------
Docker is a containerization platform used to package applications and their dependencies into portable containers.

1. WHY DOCKER MATTERS
--------------------------------------------------------------------------------
Why Docker matters

- consistent environments across local and production
- faster deployment
- simplified dependency management
- easy scaling and isolation

2. CORE CONCEPTS
--------------------------------------------------------------------------------
Core concepts

- Dockerfile: instructions to build an image
- Image: packaged application with runtime and dependencies
- Container: running instance of an image
- Registry: stores Docker images

3. DOCKERFILE EXAMPLE
--------------------------------------------------------------------------------
Dockerfile example

FROM python:3.11-slim
WORKDIR /app
COPY . /app
RUN pip install -r requirements.txt
EXPOSE 8000
CMD ["python", "app.py"]

4. BUILD COMMAND
--------------------------------------------------------------------------------
Build command

COMMANDS
----------------------------------------
docker build -t myapp:latest .

5. RUN COMMAND
--------------------------------------------------------------------------------
Run command

COMMANDS
----------------------------------------
docker run -d -p 8000:8000 myapp:latest

6. SECURITY SCANNING
--------------------------------------------------------------------------------
[SECURITY] Security scanning

COMMANDS
----------------------------------------
Trivy can scan a Docker image before it is published:
trivy image --severity HIGH,CRITICAL --exit-code 1 myapp:latest

7. TROUBLESHOOTING AND OPERATIONS
--------------------------------------------------------------------------------
In a Jenkins pipeline, build the image first and scan the exact image tag that would be promoted to a registry.

8. USEFUL COMMANDS

Useful commands

12. CONTAINER RELEASE VERIFICATION
--------------------------------------------------------------------------------
Container release verification
Compare the promoted digest with the digest tested by integration and smoke tests.
Verify the runtime user, read-only paths, capabilities, health state, and exposed ports.
Test graceful shutdown while requests are active and confirm connections drain correctly.
Record the previous digest, registry location, SBOM, signature, and rollback owner.
Remove stale local images and volumes only after checking that no recovery path depends on them.
Review registry audit logs after unexpected pulls, tag changes, or deletion events.
Check container DNS and user-defined network membership before debugging application endpoints.
Inspect mounted files and environment sources when configuration differs between hosts.
Compare container architecture with the node architecture after an exec format error.
Use a temporary diagnostic container rather than modifying the production image in place.
Confirm that a restart policy is not masking a deterministic configuration failure.
Test log rotation and verify that blocked logging cannot stop the application process.
Keep runtime images small to reduce transfer time, vulnerability surface, and storage cost.
Review Dockerfile instructions for unnecessary package managers, shells, and build tools.
Use non-root file ownership that matches the runtime UID rather than changing permissions broadly.
Document the exact command, compose profile, or orchestrator definition used to start the service.
Container operations are repeatable when image identity, runtime configuration, and data ownership are explicit.

13. IMAGE BUILD AND RUNTIME TROUBLESHOOTING
--------------------------------------------------------------------------------
Image build and runtime troubleshooting
Use a pinned builder and record the build context, source revision, and base digest.
Run docker build --pull when refreshing a base image is intentional.
Use docker history to investigate unexpected layers or copied files.
Use docker inspect to compare environment, mounts, networks, and health configuration.
Use docker exec only for controlled diagnosis, never as an undocumented production fix.
Check docker logs --since and container exit codes before restarting repeatedly.
Use docker stats to distinguish CPU pressure, memory pressure, and idle processes.
Inspect disk usage with docker system df before pruning images or volumes.
Use docker compose config to validate interpolated local configuration.
Separate development Compose files from production orchestration manifests.
Use explicit healthcheck start periods for applications with migrations or warm-up work.
Ensure the process receiving PID 1 handles SIGTERM and reaps child processes.
Set stop timeouts that allow graceful connection draining.
Keep application data in managed storage or named volumes with tested backups.
Mount configuration read-only when the process does not need to modify it.
Use tmpfs for sensitive short-lived files when the platform supports it.
Limit container processes with pids limits and resource reservations.
Use restart policies only when repeated restarts will not hide a permanent failure.
Test image behavior with missing optional dependencies and invalid configuration.
Verify that the image starts without network access when the application should be self-contained.
Test registry pull permissions using the same identity as the deployment platform.
Retain the deployed digest and previous digest for rapid rollback.
Use admission policy to reject unsigned, mutable, or privileged images.
Review image licenses and remove packages that are not required at runtime.
Schedule rebuilds for operating system security updates even when application code is unchanged.
Document ports, required capabilities, writable paths, signals, and health semantics.
Measure build cache hit rate and registry transfer time to control delivery cost.
Test multi-architecture images on each supported architecture before publication.
Container security includes the host kernel, runtime, registry, image, and application configuration.
