14. Istio Service Mesh

Route traffic, shift versions, enforce mTLS, and observe service-to-service behavior.

Service-mesh flow

Client -> Istio Ingress Gateway -> VirtualService -> DestinationRule subset | Envoy sidecars -> service workload

Project controls

Two catalog versions receive controlled traffic. The VirtualService defines routing, retries, timeout, and a 90/10 canary split. The DestinationRule defines subsets and outlier detection.

PeerAuthentication enables STRICT mTLS, while AuthorizationPolicy limits which namespaces may call the catalog service.

[SECURITY] Start with explicit authorization policies, verify sidecar injection, and test traffic behavior before enabling strict mTLS across a production mesh.
