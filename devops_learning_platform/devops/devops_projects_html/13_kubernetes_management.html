13. Kubernetes Management

Manage a production-style application namespace with security, resources, scaling, and health controls.

Management scope

This project demonstrates Kubernetes day-2 operations: namespace isolation, least-privilege RBAC, configuration, quotas, limits, network policy, rollout health, autoscaling, and disruption protection.

Apply order

kubectl apply -f namespace.yaml kubectl apply -f rbac.yaml kubectl apply -f config.yaml kubectl apply -f policies.yaml kubectl apply -f workload.yaml kubectl apply -f service.yaml kubectl apply -f autoscaling.yaml

Operate and troubleshoot

kubectl -n platform-demo get all kubectl -n platform-demo rollout status deployment/platform-api kubectl -n platform-demo get events --sort-by=.lastTimestamp kubectl -n platform-demo describe pod POD_NAME kubectl -n platform-demo rollout undo deployment/platform-api
[SECURITY] The service account can read only ConfigMaps in its namespace. Expand permissions only for a documented requirement.
[PRODUCTION] Add image signing, admission policy, secret management, backups, Pod Security standards, and tested disaster recovery before production use.

Key controls

ResourceQuota: limits namespace consumption. LimitRange: supplies safe container defaults. NetworkPolicy: reduces network reachability. HPA: scales from CPU utilization. PDB: protects availability during voluntary disruptions.
