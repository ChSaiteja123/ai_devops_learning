Day 02 of 10 | BASIC

AI-assisted coding and code review

Use AI to draft or explain changes while keeping diffs, tests, and maintainers in control.

Visual explanation

Deep dive

Bound the request

Give the assistant a specific file, behavior, and acceptance criteria. Avoid broad requests that encourage speculative edits or access to unrelated repositories.

Review the diff

Inspect every changed line, dependency, generated command, and assumption. Check correctness, security, maintainability, and compatibility, not only whether the example runs.

Keep repository gates

Use ordinary tests, code owners, linting, and review requirements. An AI summary or generated test suite is not evidence that the change is safe or complete.

Try it: Use a fictional change request and write three acceptance checks a reviewer can run without trusting the assistant's explanation.
Safety and reliability: Do not paste secrets or private source into an unapproved AI tool. Never merge solely because generated tests pass.
Mastery checkpoint: Explain "AI-assisted coding and code review", name one failure mode, and identify the relevant safety boundary.
